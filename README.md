# 家居自动化核心

这个 Go 包提供无外部设备依赖的自动化规则引擎，可用 `VirtualDevice` 构造事件，用 `FileStore` 持久化状态。

## 接入步骤

1. 用 `NewCore(store, clock)` 创建核心；生产环境传 `FileStore`，测试可传 `nil`。
2. 用 `AddRule` 注册规则，规则包含条件、持续时间、延迟动作、优先级和人工覆盖有效期；规则是配置，重启后需要先重新注册，再处理持久化待办。
3. 设备上报调用 `Process(event)`；无设备事件但需要处理到期动作时调用 `Tick(at)`。
4. 从 `PendingActions()`、`Snapshot()` 和 `Decisions()` 获取待执行动作、当前状态和执行/取消原因。

## 规则语义

- **持续条件**：`Condition` 在 `Duration` 期间必须持续为真；条件一旦变假，持续计时与已触发状态立即重置。
- **延迟动作**：持续条件满足后创建 `Action`，`SetStateAction.After` 是延迟时间。
- **到期复核**：延迟动作到期时重新检查规则、持续时间起点和当前条件；条件已失效或动作错过有效窗口时取消，不会补执行。
- **人工覆盖**：手动事件立即写入设备状态，并取消同一设备同一属性的待执行自动化动作。
- **覆盖恢复**：`Rule.ManualOverride > 0` 时，覆盖到期且条件仍为真会重新开始持续条件判断，然后生成新动作；`ManualOverride == 0` 保持兼容旧语义，需条件先变假再变真才恢复。
- **冲突裁决**：同一设备同一属性的冲突动作按 `Priority` 从高到低裁决；优先级相同则较早到期者优先，再相同按规则 ID 确定顺序。
- **循环限制**：规则生成的设备状态可触发其他规则，但每条规则在一次满足周期内只触发一次；相互触发不会持续循环。
- **重启与重放**：设备状态、规则运行态、待执行动作、事件历史和裁决日志都会持久化；`Replay(events)` 可用旧事件在新核心中重放。

## 独立演示

运行：

```bash
go run ./cmd/virtual-demo
```

演示交错覆盖以下过程：夜间条件持续一分钟、开灯延迟十五分钟、临时手动关闭、进程重启、人工覆盖有效期结束、电影模式高优先级关灯冲突、冲突条件提前结束后旧关灯动作取消、旧事件历史重放。每一步都会输出 `executed` 或 `canceled` 以及原因。
