# 智能家居自动化核心（Go）

从零搭建的设备状态、规则与动作执行引擎，重点实现“带持续条件的自动化”，
门窗与温度均为虚拟设备，事件语义对未来接入的任何设备保持一致。

## 运行与测试

```sh
go test ./...          # 全部核心语义测试
go run ./cmd/demo      # 30s 真实时钟演示，每秒落盘 demo-state.json
```

## 统一事件含义

总线上只有一种事件（`device.go`）：`某设备.某属性 从旧值变为新值 + 来源 + 因果链`。
- 设备只暴露 `Get/Set/Snapshot/Writable`，不关心调用方；门窗的 `open`(bool)、
  温度的 `temp`(number) 与后续新设备完全同构。
- 来源有三种：`manual`（人，最高优先）、`system`（设备/虚拟环境反馈）、
  `auto`（规则动作）。
- 温度传感器只读，由虚拟环境（`env.go`）更新；门窗/空调可写。

## 规则与持续条件（`rule.go` / `engine.go`）

- 规则 = 一组需同时成立的条件 + `SustainFor` 持续时长 + 多步动作序列。
- 条件为“假→真边沿”后开始计时；中途任意一次不成立，计时立即作废。
  温度短暂越界不会触发，持续满足到期才触发。
- 每个“真周期”只触发一次：条件持续成立不会每个 tick 重复动作，
  必须先变假再重新变真并持续，才进入下一周期。
- 动作支持多步、步间延时（如先开空调、10s 后仍高温再开窗），
  每一步都是带绝对到期时间的“未完成动作”。

## 手动接管

- `Engine.ManualSet` 立即生效并对该“设备+属性”加接管锁。
- 锁存在期间，针对该目标的自动动作只计数为 `Suppressed`，绝不覆盖人的操作。
- `ReleaseOverride` 解除后也不会立刻补动作（边沿语义）；需等条件经历一次
  假→真的新周期，规则才能再次控制该目标。

## 防止触发环

每个动作步骤携带触发它的“祖先规则链”（`Trace`）。规则 A 的动作引起新状态、
再满足 B、B 又满足 A 时，A 在链中已出现，闭环那一步被丢弃（计入 `Blocked`）。
另有 `maxCascade` 与 `maxActionsPerPump` 作为硬上限。测试用 4 条规则构成的
振荡器（0→1→2→3→0）验证它会稳定停下而不是无限递归。

## 重启续跑（`persistence.go`）

快照包含：引擎时刻、每条规则的持续计时（到期点 + 本周期是否已触发）、
所有未完成动作步骤、手动接管锁、各设备属性。
恢复方式：先重建同样的设备与规则，再 `LoadFromFile`；
- 尚未到期的持续计时继续，不会因重启提前/重复触发；
- 未完成动作按绝对到期时间继续执行（包括重启瞬间已到期的步骤）；
- 接管锁跨重启保留。

`engine_test.go` 的 `TestRestartResumesTimersAndPending` 用两条互相影响的规则
（高温→开空调/开窗；开窗持续→关空调）并在途中多次重启验证以上行为。

## 文件

- `device.go`：Value/Bus/Device/VirtualDevice 与事件语义
- `rule.go`：条件、运算、规则、动作步骤模型
- `clock.go`：真实时钟与可控虚拟时钟（毫秒）
- `engine.go`：持续计时、触发边沿、手动接管、防环、动作调度
- `persistence.go`：快照序列化、原子写文件与恢复
- `env.go`：虚拟物理环境与两条互相影响的示例规则
- `cmd/demo`：真实时钟 + 周期落盘的可运行演示
